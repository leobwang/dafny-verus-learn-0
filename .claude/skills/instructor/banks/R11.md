### K1 [reconstruct] — a tree is data until the rule reads it
**viva:** yes · **tags:** `datatypes-and-match`, `verified-metatheory`, `fuel`, `sequences-and-views` · **backward-edge:** none

For the regex `Alt(Chr('p'), Cat(Chr('q'), Chr('r')))` and the word `"qr"`, write down a `Derivation` that A4's rule relation accepts (`CheckDeriv` in Dafny, `valid_word_r10` in Verus), and walk the relation through it node by node. Then take the same inner tree under `DAltL` instead of `DAltR`: is that a value of the type, and what does the relation say about it? Reconstruct, in your own words, why a certificate is data and not a proof.

**Target insights**
- `Derivation` is an ordinary datatype. Every tree of its constructors is a value, whatever it is paired with: `DAltL(DCat(1, DChr, DChr))` type-checks as well as `DAltR(DCat(1, DChr, DChr))`. A tree means something only through the rule relation, which reads the tree, the regex and the word together; the tree is untrusted until the relation accepts it.
- The accepted tree is `DAltR(DCat(1, DChr, DChr))`. The relation matches each node's constructor against the regex at that position: `DAltR` against the `Alt`, passing the whole word to the right branch; `DCat(1, …)` against `Cat(Chr('q'), Chr('r'))`, giving `"q"` to the left child and `"r"` to the right; each `DChr` checks that its word is exactly the regex's one character. A `DChr` leaf carries no character: the character comes from the regex.
- Under `DAltL` the inner tree is checked against `Chr('p')`, and the `DCat` case needs a `Cat`: the relation fails one level down. Dafny's `related:` line points at the `DAltL` case of A4's relation (`RG_A4_Norm.dfy:119:43`, its recursive conjunct); Verus reports only the assertion.
- In Verus the relation is a recursive spec fn: three levels of tree need `reveal_with_fuel(valid_word_r10, 3)`. The relation slices with `take` and `skip`, so the probe states `s.take(1) =~= seq!['q']` and `s.skip(1) =~= seq!['r']` before the `DChr` cases can compare against `seq![r->Chr_0]`. Dafny evaluates the literal slices itself.

**Misconceptions & counter-moves**
- *"A `Derivation` value is a proof that the word matches."* → Ask: what does the datatype declaration constrain, and who decides whether `DAltL(DCat(1, DChr, DChr))` means anything for `"qr"`?
- *"The `DChr` leaf says which character it read."* → Ask: which field of the `DChr` constructor would hold it, and where does the relation's `DChr` case get the character it compares with?
- *"The failing Dafny lemma failed at the `DCat` node, so the bad node is the split."* → Ask: which line of A4's relation does the `related:` location name, and which regex does that case hand to the inner tree?

### K2 [predict] — four trees, one word
**viva:** yes (verifier-refereed predict) · **tags:** `datatypes-and-match`, `sequences-and-views`, `verdict-reading`, `fuel` · **backward-edge:** none

Four certificates for `Cat(Star(Chr('x')), Chr('y'))` on the word `"xxy"`: [a] `DCat(2, DStarCons(1, DChr, DStarCons(1, DChr, DStarNil)), DChr)`; [b] the same tree with root split 3; [c] `DCat(1, DStarCons(1, DChr, DStarNil), DChr)`; [d] `DCat(2, DStarCons(2, DChr, DStarNil), DChr)`. **Target insights**
- Every split is relative to the word its node owns. In [a] the root owns `"xxy"` and gives `"xx"` to the star and `"y"` to `Chr('y')`; the outer `DStarCons(1, …)` owns `"xx"`, so its 1 cuts `"xx"`, not `"xxy"`; the inner `DStarCons(1, …)` owns `"x"`, and `DStarNil` owns the empty word. [a] is valid.
- [b] gives the star all of `"xxy"`: two one-scalar chunks leave `"y"` for `DStarNil`, which needs the empty word, so the left child fails (and the right child, `DChr` on the empty word, would fail too). [c] gives the star one chunk `"x"`, which is fine, and gives `Chr('y')` the word `"xy"`: the right child fails. [d] gives one `DChr` a chunk of two scalars: the left child fails. The answer: `D:FAILS b c d V:FAILS b c d`.
- Dafny names the conjunct: in A4's `DCat` case on line 122, column 39 is the left child's `CheckDeriv(r.a, s[..k], d1)` and column 70 the right child's `CheckDeriv(r.b, s[k..], d2)`. [b] and [d] point at 39, [c] at 70: Dafny reports the first conjunct it cannot prove. Verus reports only the assertion lines.
- Only root split 2 admits a valid tree here: `Chr('y')` must own exactly the last scalar, and `Chr('x')` matches one scalar per chunk, so the star's tree is forced too.

**Misconceptions & counter-moves**
- *"[a]'s inner split 1 points at the first `x` of `"xxy"`, so both chunks are the same `x`."* → Ask: which word does each `DStarCons` node own, and what is `s[..1]` of it?
- *"[d] is fine: `"xx"` is in the language of `Star(Chr('x'))`."* → Ask: which regex does the chunk's `DChr` leaf answer to, and how many scalars does its case allow?
- *"[b] fails because `Chr('y')` gets the empty word."* → Ask: which column of line 122 does Dafny name for [b], and which child is that?

### K5 [reconstruct] — agreement by recursion on the certificate
**viva:** yes · **tags:** `verified-metatheory`, `induction-as-recursion`, `datatypes-and-match`, `quantifiers` · **backward-edge:** none

A fresh certificate system: a path `PathBankR11` through a binary tree `TreeBankR11` certifies that the path ends at a leaf holding `v`; the rule relation is `LandsBankR11`, and the checker `FollowBankR11` follows the path and returns the leaf's value or nothing. State checker agreement for this system, and reconstruct its proof: what is the induction on, how many recursive calls does each case need, and under which test? Then say what breaks if the checker's `Stop` case forgets to test that it stands on a leaf.

```dafny
module R11_BankPathAgree {
  datatype TreeBankR11 = LeafBankR11(v: int) | NodeBankR11(l: TreeBankR11, r: TreeBankR11)
  datatype PathBankR11 = StopBankR11 | LeftBankR11(p: PathBankR11) | RightBankR11(p: PathBankR11)
  datatype OptBankR11 = NoneBankR11 | SomeBankR11(x: int)

  // The relation: path p leads from t to a leaf that holds v.
  ghost predicate LandsBankR11(t: TreeBankR11, p: PathBankR11, v: int)
  {
    match p
    case StopBankR11 => t.LeafBankR11? && t.v == v
    case LeftBankR11(q) => t.NodeBankR11? && LandsBankR11(t.l, q, v)
    case RightBankR11(q) => t.NodeBankR11? && LandsBankR11(t.r, q, v)
  }

  // The checker: follow the path, or report that it leaves the tree.
  function FollowBankR11(t: TreeBankR11, p: PathBankR11): OptBankR11
  {
    match p
    case StopBankR11 => if t.LeafBankR11? then SomeBankR11(t.v) else NoneBankR11
    case LeftBankR11(q) => if t.NodeBankR11? then FollowBankR11(t.l, q) else NoneBankR11
    case RightBankR11(q) => if t.NodeBankR11? then FollowBankR11(t.r, q) else NoneBankR11
  }

  // Agreement, by recursion on the path: one call per child the checker visits.
  lemma {:induction false} FollowAgreesBankR11(t: TreeBankR11, p: PathBankR11, v: int)
    ensures FollowBankR11(t, p) == SomeBankR11(v) <==> LandsBankR11(t, p, v)
    decreases p
  {
    match p
    case StopBankR11 =>
    case LeftBankR11(q) =>
      if t.NodeBankR11? {
        FollowAgreesBankR11(t.l, q, v);
      }
    case RightBankR11(q) =>
      if t.NodeBankR11? {
        FollowAgreesBankR11(t.r, q, v);
      }
  }
}
```

```rust
    Right(Box<PathBankR11>),

    decreases p,
{

        PathBankR11::Stop => t is Leaf && t->Leaf_0 == v,
        PathBankR11::Left(q) => t is Node && lands_bank_r11(*t->Node_0, *q, v),

    ensures
        forall|v: i64| o == Some(v) <==> #[trigger] lands_bank_r11(*t, *p, v),
    decreases p,

        PathBankR11::Stop => match t {
            TreeBankR11::Leaf(v) => Some(*v),
            TreeBankR11::Node(_, _) => None,
        },

            TreeBankR11::Node(l, _) => {
                assert(forall|w: i64| #[trigger] lands_bank_r11(*t, *p, w) == lands_bank_r11(**l, **q, w));

                assert(forall|w: i64| #[trigger] lands_bank_r11(*t, *p, w) == lands_bank_r11(**r, **q, w));
                follow_bank_r11(r, q)
            },
            TreeBankR11::Leaf(_) => None,
        },

}

} // verus!
```

### K6 [why] — why a Verus split needs a length bound
**viva:** yes · **tags:** `nat-vs-machine-int`, `sequences-and-views`, `spec-vs-exec` · **backward-edge:** none

R11's Verus completeness promise carries a hypothesis its Dafny twin lacks: the word must fit a `usize`. Explain why, from the type of A4's `DCat` field in each language. The probe stores a split point `i` of a spec word in a `DCat` and reads it back, with and without the bound; the Dafny probe does the same with A4's `nat` field and with a bounded field of its own.

**Target insights**
- Dafny's `DCat(k: nat, …)` stores any split of any word: `NatSplitBankR11` verifies with no bound. Verus's `DCat(usize, …)` shares its type with exec code, so its split is a machine integer, while a spec word `Seq<char>` has a mathematical length that can exceed `usize::MAX`.
- In spec code, `i as usize` for an `i` outside the range is a truncation the solver knows nothing useful about, so `(i as usize) as int == i` is unprovable for an arbitrary split (line 12). Under `s.len() <= usize::MAX` every split `0 <= i <= s.len()` round-trips, the stored split reads back as the intended one, and `s.take(k as int)` is `s.subrange(0, i)`: the bounded probe verifies.
- A theorem that builds a certificate from a membership proof must therefore assume the word fits; a theorem that only consumes a given certificate never meets the problem, because the tree already holds machine values. Dafny meets the same question as soon as the field is bounded: storing `i` in a `0 <= x < 256` newtype fails without `|s| < 256` (line 19, column 26).

**Misconceptions & counter-moves**

### K11 [transfer] — a closed table of indices
**viva:** yes · **tags:** `frames`, `sequences-and-views`, `ownership-and-mut-ref` · **backward-edge:** R10 (a predicate every value carries, which each operation must re-establish)

A table of indices is closed when every entry is a valid index of the same table. Three operations: [grow] append an entry that points at an existing slot; [self] append an entry that points at itself; [retarget] overwrite one slot with an unchecked target. Before running anything, decide which keep the table closed and why; then transfer the reasoning to R11's Vec-backed arena: which of its invariants is "targets in range", which is "monotone under growth", and where does the frame of `set` enter?

```dafny
module R11_BankPointers {
  // Every slot points at a slot of the same table.
  ghost predicate ClosedBankR11(s: seq<nat>)
  {
    forall i :: 0 <= i < |s| ==> s[i] < |s|
  }

  // [grow] append a slot that points at an existing slot
  method GrowBankR11(s: seq<nat>, j: nat) returns (t: seq<nat>)
    requires ClosedBankR11(s) && j < |s|
    ensures ClosedBankR11(t) && |t| == |s| + 1 && t[..|s|] == s
  {
    t := s + [j];
  }

  // [self] append a slot that points at itself
  method GrowSelfBankR11(s: seq<nat>) returns (t: seq<nat>)
    requires ClosedBankR11(s)
    ensures ClosedBankR11(t) && |t| == |s| + 1 && t[..|s|] == s
  {
    t := s + [|s|];
  }

  // [retarget] overwrite a slot with an unchecked target
  method RetargetBankR11(s: seq<nat>, i: nat, j: nat) returns (t: seq<nat>)
    requires ClosedBankR11(s) && i < |s|
    ensures ClosedBankR11(t)
  {
    t := s[i := j];
  }
}
```

```rust
// Every slot points at a slot of the same table.

    forall|i: int| 0 <= i < s.len() ==> s[i] < s.len()
}

// [grow] append a slot that points at an existing slot
fn grow_bank_r11(v: &mut Vec<usize>, j: usize)
    requires
        closed_bank_r11(old(v)@),
        j < old(v).len(),
    ensures
        closed_bank_r11(final(v)@),
        final(v)@.take(old(v).len() as int) == old(v)@,
{
    v.push(j);
    assert(v@.take(old(v).len() as int) =~= old(v)@);
}

// [self] append a slot that points at itself
fn grow_self_bank_r11(v: &mut Vec<usize>)
    requires
        closed_bank_r11(old(v)@),
    ensures
        closed_bank_r11(final(v)@),
        final(v)@.take(old(v).len() as int) == old(v)@,
{
    let n = v.len();
    v.push(n);
    assert(v@.take(old(v).len() as int) =~= old(v)@);
}

// [retarget] overwrite a slot with an unchecked target
fn retarget_bank_r11(v: &mut Vec<usize>, i: usize, j: usize)
    requires
        closed_bank_r11(old(v)@),
        i < old(v).len(),
    ensures
        closed_bank_r11(final(v)@),
{
    v.set(i, j);
}

} // verus!
```

**Target insights**
- Closure is a property of the whole table, and each operation must re-establish it. [grow] keeps it by monotonicity: an old entry is below the old length, which is below the new length, and the new entry is below the old length by its precondition. [self] keeps it too: its target is the old length, which is a valid index after the push. The range check is against the state after the operation, not before.
- [retarget] breaks it: the frame of the update keeps every other slot, but the written slot holds an arbitrary `j`, and nothing says `j < |s|`. Dafny names the predicate's `forall` (line 5); Verus names the postcondition (line 42). The fix is a precondition on the target, the same shape as the arena's edge writer.
- The arena carries the same three facts: every stored target is in range (the closure invariant); growing keeps every earlier node valid (monotone, so the old proofs need not be redone); and a `set` changes one slot and, by its frame, nothing else, so the closure of every other slot is inherited. While authoring, Dafny's [grow] and [self] first failed with *"upper bound below lower bound or above length of sequence"* at `t[..|s|]`, until the postcondition said `|t| == |s| + 1` first: a well-formedness obligation, K4's lesson again.

**Misconceptions & counter-moves**
- *"[self] fails: the entry points one past the end."* → Ask: past the end of which table, the one before or after the push?
- *"[retarget] keeps the other slots, so it keeps closure."* → Ask: what does closure demand of the written slot itself?
- *"After a push every old proof about the table must be redone."* → Ask: which facts about an old entry mention the length, and in which direction does the length move?

### K12 [transfer] — the evidence a consumer demands
**viva:** yes · **tags:** `requires-ensures`, `ghost-and-modes`, `tracked-ghost`, `tcb` · **backward-edge:** R08 (a client of an interface knows only its obligations)

A consumer reports a membership only when handed evidence: a ghost index `i` with `i < |s| && s[i] == x`. A producer scans for `x` but its contract promises only that its answer is in range. Two clients: [checked] re-checks the answer before calling the consumer; [trusting] checks only the range. Transfer R11's trust story: which client verifies, what has the check bought, and what does a failed check refute? Then the Verus-only part: the same evidence as a tracked value, handed to two consumers.

```dafny
module R11_BankEvidence {
  // The consumer: its precondition names the evidence that x occurs in s.
  method ReportBankR11(s: seq<int>, x: int, ghost i: nat) returns (b: bool)
    requires i < |s| && s[i] == x
    ensures b && x in s
  {
    b := true;
  }

  // The producer: a scan whose contract promises only a range.
  method GuessBankR11(s: seq<int>, x: int) returns (k: nat)
    ensures k <= |s|
  {
    k := 0;
    while k < |s| && s[k] != x
      invariant k <= |s|
      decreases |s| - k
    {
      k := k + 1;
    }
  }

  // [checked] the client re-checks the producer's answer
  method CheckedBankR11(s: seq<int>, x: int)
  {
    var k := GuessBankR11(s, x);
    if k < |s| && s[k] == x {
      var b := ReportBankR11(s, x, k);
    }
  }

  // [trusting] the client checks only the range
  method TrustingBankR11(s: seq<int>, x: int)
  {
    var k := GuessBankR11(s, x);
    if k < |s| {
      var b := ReportBankR11(s, x, k);
    }
  }
}
```
