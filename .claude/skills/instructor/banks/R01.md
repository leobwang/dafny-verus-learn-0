## Questions

### K1 [reconstruct] — responsibility at a call
**viva:** yes · **tags:** `requires-ensures` · **backward-edge:** none

Reconstruct the responsibilities at a call to a routine with one precondition and one postcondition. Which side may assume each formula, and which side must establish it? Explain what changes if the precondition is made stronger.

**Target insights**
- The caller owes the precondition; the body gets it as an assumption. The body owes the postcondition on return; the caller receives it.
- A stronger precondition removes promised calls. A green implementation is not evidence that all intended clients remain admitted.

**Misconception → counter-move.** “Requires documents what the function checks at runtime.” Ask where the promised check occurs in the body and which obligation the caller sees before the call.

**Incomplete → narrow.** Ask who establishes the formula before the implementation starts. **Off-track → anchor.** Return to one caller and one declaration. **Correct → deepen.** Ask what a contradictory precondition would do to usefulness.

### K3 [reconstruct] — a proof call is not an executable answer
**viva:** yes · **tags:** `lemma-call`, `spec-vs-exec` · **backward-edge:** none

A supplied lemma establishes a bound on a recursive specification function. Explain what becomes available when another proof calls it, and why merely placing that lemma earlier in the file is not the same action. What remains in the compiled program?

**Target insights.** A call supplies the proved postcondition instantiated at the call arguments. Ghost proof work is erased from executable behaviour. The logical account and the executable computation have distinct roles.

**Misconception → counter-move.** “The lemma computes the bounded value.” Ask for the result type and the postcondition being exported. **Incomplete → narrow.** Ask what the caller knows immediately after the call. **Off-track → anchor.** Return to the given bound lemma. **Correct → deepen.** Ask why a needed fact may still be missing at another call site.

### K7 [reconstruct] — tests and proof have different populations
**viva:** yes · **tags:** `spec-vs-exec`, `verdict-reading` · **backward-edge:** none

A small compiled test passes. Explain which executions it observed and how that differs from verification under a routine's precondition. Where must you look before claiming that the test body itself was verified?

**Target insights.** A passing test is evidence about executions reached by that test. Verification covers formal obligations on the admitted domain. A language or harness may compile test code outside the verified fragment; inspect the boundary instead of transferring guarantees by filename.

**Misconception → counter-move.** “Calling a verified function verifies the test.” Ask whether the caller's own statements were submitted to the verifier. **Incomplete → narrow.** Ask for one input the test did not run. **Off-track → anchor.** Name the command and source mode. **Correct → deepen.** Ask why an excluded call cannot claim the routine's verified promise.

### K9 [explain-back] — a recursive call earns its hypothesis

### PP1 — parallel to R01.H2d and R01.H2v
**Isolates:** `induction-as-recursion`, `termination-measure`.

A function retains positions 0, 2, 4 and so on. Prove that it cannot increase the sequence length. The recursive step removes two positions; identify the smaller-input fact and how it relates to the current result. Work in scratch under the R01 wrapper context.

```dafny
module R01_ParallelSparse {
  function SparseChars(s: seq<char>): seq<char>
    decreases |s|
  { if |s| < 2 then s else [s[0]] + SparseChars(s[2..]) }
  lemma {:induction false} SparseCharsBound(s: seq<char>)
    ensures |SparseChars(s)| <= |s|
    decreases |s|
}
```

```rust
use vstd::prelude::*;
verus! {
pub open spec fn sparse_chars(s: Seq<char>) -> Seq<char>
    decreases s.len(),
{ if s.len() < 2 { s } else { seq![s[0]] + sparse_chars(s.subrange(2, s.len() as int)) } }
proof fn lemma_sparse_chars_bound(s: Seq<char>)
    ensures sparse_chars(s).len() <= s.len(),
    decreases s.len(),
{ #[verifier::proof_note("parallel")] assume(false); }
}
```
