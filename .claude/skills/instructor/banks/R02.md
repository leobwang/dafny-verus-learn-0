### K1 [reconstruct] — every case covered, one case wrong
**viva:** yes · **tags:** `datatypes-and-match`, `verdict-reading` · **backward-edge:** none

Reconstruct, from A1's declaration alone, the arms a function over `Re` must have, and what each arm binds. Then read the probe: `AltTally` / `alt_tally` is meant to count the `Alt` nodes of a regex. Its `match` covers every constructor. What does the sample check report in each language, and what does that say about exhaustiveness?

```dafny
module R02_BankAltTally {
  import opened RG_A1_Re

  // The number of Alt nodes. Every constructor is covered.
  function AltTally(r: Re): nat
    decreases r
  {
    match r
    case Alt(a, b) => 1 + AltTally(a) + AltTally(b)
    case Cat(a, b) => AltTally(a) + AltTally(b)
    case Star(a) => 1 + AltTally(a)
    case _ => 0
  }

  lemma AltTallySample()
    ensures AltTally(Alt(Eps, Star(Eps))) == 1
  {
  }
}
```
```rust
use vstd::prelude::*;
use rg_re_a1::*;

verus! {

// The number of Alt nodes. Every constructor is covered.
spec fn alt_tally(r: Re) -> nat
    decreases r,
{
    match r {
        Re::Alt(a, b) => 1 + alt_tally(*a) + alt_tally(*b),
        Re::Cat(a, b) => alt_tally(*a) + alt_tally(*b),
        Re::Star(a) => 1 + alt_tally(*a),
        _ => 0,
    }
}

proof fn lemma_alt_tally_sample() {
    assert(alt_tally(Re::Alt(Box::new(Re::Eps), Box::new(Re::Star(Box::new(Re::Eps))))) == 1) by (compute_only);
}

} // verus!
```

**Target insights**
- Six constructors, so six shapes; a binary constructor binds two `Re` fields (Verus: two `Box<Re>`), `Star` one, `Chr` a `char`, and the wildcard `_` covers the rest. Exhaustiveness is a property of the arms, checked before or beside verification; it says every shape has *some* result.
- The `Star` arm adds 1 although a `Star` is not an `Alt`: the function is total and wrong. The sample `Alt(Eps, Star(Eps))` has one `Alt` and the function says 2. Only a stated expectation (here a contract on a sample) catches a wrong branch; the coverage check cannot.
- Each language reports it at its own place: Dafny as the lemma's postcondition; Verus's `by (compute_only)` evaluates the expression during the front end and reports the false equation it simplified to (`2 == 1`) at `stage resolve`.

**Misconceptions & counter-moves**
- *"The match is exhaustive, so the function is correct."* → Ask: which arm would you change to make the sample hold, and which check told you so?
- *"A `stage resolve` error is a syntax error."* → Ask: what did `compute_only` compute here, and what does the message say the expression became?

### K2 [predict] — how much of a split must be said
**viva:** yes (verifier-refereed predict) · **tags:** `witnesses`, `anchoring`, `fuel`, `quantifiers` · **backward-edge:** none

Four proofs of `Matches(Cat(Chr('p'), Chr('q')), ['p', 'q'])`, one per label: [a] states only the prefix slice at 1; [b] states both slices at 1; [c] states both slices and both sides' matches; [d] states both slices at 2 (the wrong split). Predict which labels fail in each language. Answer form `D:FAILS <labels> V:FAILS <labels>` (or `none`).

```dafny
module R02_BankPQ {
  import opened RG_A1_Re

  // [a] the prefix slice only
  lemma PQa()
    ensures Matches(Cat(Chr('p'), Chr('q')), ['p', 'q'])
  {
    assert ['p', 'q'][..1] == ['p'];
  }

  // [b] both slices
  lemma PQb()
    ensures Matches(Cat(Chr('p'), Chr('q')), ['p', 'q'])
  {
    assert ['p', 'q'][..1] == ['p'];
    assert ['p', 'q'][1..] == ['q'];
  }

  // [c] both slices and both sides
  lemma PQc()
    ensures Matches(Cat(Chr('p'), Chr('q')), ['p', 'q'])
  {
    assert ['p', 'q'][..1] == ['p'];
    assert ['p', 'q'][1..] == ['q'];
    assert Matches(Chr('p'), ['p', 'q'][..1]);
    assert Matches(Chr('q'), ['p', 'q'][1..]);
  }

  // [d] the wrong split, both slices named
  lemma PQd()
    ensures Matches(Cat(Chr('p'), Chr('q')), ['p', 'q'])
  {
    assert ['p', 'q'][..2] == ['p', 'q'];
    assert ['p', 'q'][2..] == [];
  }
}
```
```rust

use rg_re_a1::*;

verus! {

spec fn pq() -> Re {
    Re::Cat(Box::new(Re::Chr('p')), Box::new(Re::Chr('q')))
}

// [a] the prefix slice only
proof fn lemma_pq_a() ensures matches(pq(), seq!['p', 'q']), {
    let s = seq!['p', 'q'];
    assert(s.subrange(0, 1) =~= seq!['p']);
}

// [b] both slices
proof fn lemma_pq_b() ensures matches(pq(), seq!['p', 'q']), {
    let s = seq!['p', 'q'];
    assert(s.subrange(0, 1) =~= seq!['p']);
    assert(s.subrange(1, 2) =~= seq!['q']);
}

// [c] both slices and both sides
proof fn lemma_pq_c() ensures matches(pq(), seq!['p', 'q']), {
    let s = seq!['p', 'q'];
    assert(s.subrange(0, 1) =~= seq!['p']);
    assert(s.subrange(1, 2) =~= seq!['q']);
    assert(matches(Re::Chr('p'), s.subrange(0, 1)));
    assert(matches(Re::Chr('q'), s.subrange(1, 2)));
}

// [d] the wrong split, both slices named
proof fn lemma_pq_d() ensures matches(pq(), seq!['p', 'q']), {
    let s = seq!['p', 'q'];
    assert(s.subrange(0, 2) =~= s);
    assert(s.subrange(2, 2) =~= Seq::<char>::empty());
}

} // verus!
```

**Target insights**
- One index carries both conjuncts. At 2 the right side is `Chr('q')` on `[]`, which is false, so [d] fails in both languages whatever is stated: the wrong candidate cannot be rescued by more facts about it.
- Dafny needs only the term that names the candidate: once `['p', 'q'][..1]` is in play the solver evaluates the rest, so [a], [b] and [c] verify. Verus unfolds a recursive spec fn one level per mention: the goal's `matches` on the `Cat` opens, but the `matches` on each side stays closed until it is mentioned, so [a] and [b] fail and [c], which asserts each side's match, verifies. That is why W1v asserts both sides.
- The answer: `D:FAILS d V:FAILS a b d`.

**Misconceptions & counter-moves**
- *"Naming both slices is the whole witness in every language."* → Probe: Verus [b]; ask: which `matches` term in [c] is new, and why does mentioning it help?
- *"Any split with true slice facts proves the match."* → Ask: at index 2, what string does `Chr('q')` receive?

### K3 [predict] — a chunk that may be empty
**viva:** yes (verifier-refereed predict) · **tags:** `termination-measure`, `verdict-reading` · **backward-edge:** none

`OChunks(s)` says that `s` splits into chunks that are runs of `'o'`. The first version lets a chunk be empty (`0 <= i`); the second requires `0 < i` (Verus `1 <= i`). Both are measured by the string's length. Predict each language's verdict for each version: `D:<first>,<second> V:<first>,<second>`, each `ok` or `fail`.

```dafny
module R02_BankChunks {
  // Every chunk is a run of 'o's; the first chunk may be empty.
  ghost predicate OChunks(s: seq<char>)
    decreases |s|
  {
    s == [] || exists i | 0 <= i <= |s| :: (forall k | 0 <= k < i :: s[k] == 'o') && OChunks(s[i..])
  }
}
```
```dafny
module R02_BankChunksFixed {
  // Every chunk is a non-empty run of 'o's.
  ghost predicate OChunks(s: seq<char>)
    decreases |s|
  {
    s == [] || exists i | 0 < i <= |s| :: (forall k | 0 <= k < i :: s[k] == 'o') && OChunks(s[i..])
  }
}
```
```rust
use vstd::prelude::*;

verus! {

// Every chunk is a run of 'o's; the first chunk may be empty.
spec fn o_chunks(s: Seq<char>) -> bool
    decreases s.len(),
{
    s.len() == 0 || exists|i: int|
        0 <= i <= s.len() && (forall|k: int| 0 <= k < i ==> s[k] == 'o') && o_chunks(
            #[trigger] s.subrange(i, s.len() as int),
        )
}

} // verus!
```
(The Verus second version is the same file with `1 <= i` and the comment "every chunk is non-empty".)

**Target insights**
- The recursive call is `OChunks(s[i..])`. With `i = 0` allowed, it is `OChunks(s)`: the measure `|s|` does not decrease, and the definition is refused at that call. The witness the existential *might* choose is what the measure must cover, not the one a reader expects.
- With `0 < i`, every call drops at least one character: `D:fail,ok V:fail,ok`.
- A refused definition is not a looping program: nothing runs. It is a definition that has not justified itself, and nothing after it can be trusted to mean anything.

**Misconceptions & counter-moves**
- *"The solver would never pick `i = 0`, so the first version is fine."* → Ask: what must hold for *every* `i` the existential admits?
- *"It verifies once the body is correct."* → Ask: which obligation fails, and does it mention the body's meaning at all?

### K4 [predict] — three calls, one pair
**viva:** yes (verifier-refereed predict) · **tags:** `termination-measure`, `verdict-reading` · **backward-edge:** none

Three definitions share the measure `decreases r, |s|` (Verus `decreases r, s.len()`). [x] calls itself on a strict child with a **longer** string; [y] on the same regex with a shorter string; [z] on the same regex with the same string read backwards. Predict which are refused, in each language: `D:FAILS <labels> V:FAILS <labels>`.

```dafny
module R02_BankPairs {
  import opened RG_A1_Re

  // [x] a strict child, with a longer string
  ghost predicate Px(r: Re, s: seq<char>)
    decreases r, |s|
  {
    match r
    case Star(a) => Px(a, s + s + ['z'])
    case _ => true
  }

  // [y] the same regex, a shorter string
  ghost predicate Py(r: Re, s: seq<char>)
    decreases r, |s|
  {
    if |s| == 0 then true else Py(r, s[1..])
  }

  // [z] the same regex, the same string read backwards
  ghost predicate Pz(r: Re, s: seq<char>)
    decreases r, |s|
  {
    if |s| == 0 then true else Pz(r, BackwardsStr(s))
  }
}
```
```rust
use vstd::prelude::*;
use rg_re_a1::*;

verus! {

// [x] a strict child, with a longer string
spec fn px(r: Re, s: Seq<char>) -> bool
    decreases r, s.len(),
{
    match r {
        Re::Star(a) => px(*a, s + s + seq!['z']),
        _ => true,
    }
}

// [y] the same regex, a shorter string
spec fn py(r: Re, s: Seq<char>) -> bool
    decreases r, s.len(),
{
    if s.len() == 0 {
        true
    } else {
        py(r, s.subrange(1, s.len() as int))
    }
}

// [z] the same regex, the same string read backwards
spec fn pz(r: Re, s: Seq<char>) -> bool
    decreases r, s.len(),
{
    if s.len() == 0 {
        true
    } else {
        pz(r, backwards_str(s))
    }
}

} // verus!
```

**Target insights**
- A lexicographic pair compares the first coordinate first. [x]'s first coordinate drops (a child), which settles it: the longer string does not matter. [y] keeps the first and drops the second. [z] keeps both: reading backwards does not change the length.
- So `D:FAILS z V:FAILS z`. "Both coordinates must decrease" is the common wrong rule, and it would refuse [x].
- The pair is exactly `Matches`' measure: `Star`'s body call is [x]'s shape (a child, and a slice whose length does not matter), its tail call is [y]'s.

**Misconceptions & counter-moves**
- *"[x] fails because the string grows."* → Ask: when the first coordinates differ, is the second consulted at all?
- *"[z] decreases because `BackwardsStr` is recursive."* → Ask for `|BackwardsStr(s)|` against `|s|`.

### K5 [reconstruct] — what a recursive call gives its caller
**viva:** yes · **tags:** `induction-as-recursion`, `requires-ensures`, `termination-measure` · **backward-edge:** R01 (a lemma's postcondition is what a call exports)

Reconstruct the induction for "the depth of a regex is below its node count", where `Depth` is the longest root-to-leaf path. Which arms need which calls, and why? Then read the probe, which omits one call in the `Cat` arm.

```dafny
module R02_BankDepthHalf {
  import opened RG_A1_Re

  // The longest root-to-leaf path, in edges.
  function Depth(r: Re): nat
    decreases r
  {
    match r
    case Alt(a, b) => 1 + (if Depth(a) < Depth(b) then Depth(b) else Depth(a))
    case Cat(a, b) => 1 + (if Depth(a) < Depth(b) then Depth(b) else Depth(a))
    case Star(a) => 1 + Depth(a)
    case _ => 0
  }

  lemma {:induction false} DepthBelowNodes(r: Re)
    ensures Depth(r) < NodeCount(r)
    decreases r
  {
    match r
    case Alt(a, b) =>
      DepthBelowNodes(a);
      DepthBelowNodes(b);
    case Cat(a, b) =>
      DepthBelowNodes(a);
    case Star(a) =>
      DepthBelowNodes(a);
    case _ =>
  }
}
```
```rust
use vstd::prelude::*;
use rg_re_a1::*;

verus! {

// The longest root-to-leaf path, in edges.
spec fn depth(r: Re) -> nat
    decreases r,
{
    match r {
        Re::Alt(a, b) => 1 + if depth(*a) < depth(*b) { depth(*b) } else { depth(*a) },
        Re::Cat(a, b) => 1 + if depth(*a) < depth(*b) { depth(*b) } else { depth(*a) },
        Re::Star(a) => 1 + depth(*a),
        _ => 0,
    }
}

proof fn lemma_depth_below_nodes(r: Re)
    ensures
        depth(r) < node_count(r),
    decreases r,
{
    match r {
        Re::Alt(a, b) => {
            lemma_depth_below_nodes(*a);
            lemma_depth_below_nodes(*b);
        },
        Re::Cat(a, b) => {
            lemma_depth_below_nodes(*a);
```

```dafny
    assert CatTotal(Cat(Cat(Eps, Eps), Star(Eps))) == 2;
```

**Target insights**
- The two shipped checks hold no `Alt`, so they cannot tell "counts `Cat`" from "counts `Cat` and `Alt`". The partial contract says nothing about either. An adversarial check must follow from the prose and separate the two readings: `CatTotal(Alt(Eps, Eps)) == 0` does.
- A green gate on a spec-first file means the delivery meets its formal contract and its checks; the prose is the reader's to enforce, by checks that encode it. This is R01's "contract, not intent" at the scale of a delivery.
- In rung 2 the learner's work after the contractor's run is exactly this: find what the suite leaves open, write the check, and say which plausible wrong implementation it kills. A property test (every regex without a `Cat` has total 0) is the general form.

**Misconceptions & counter-moves**
- *"It passed every check, so it is correct."* → Ask: which constructor did no check contain?
- *"Strengthen the contract instead."* → Ask: whose file is the contract in, and what does the rung-2 exercise allow the learner to edit?
