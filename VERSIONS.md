# VERSIONS.md: external claims and their verification

Every claim this course makes about the outside world has a row here (spec §8.7). Re-verify every row on any toolchain bump and before a chapter relies on it.

- **Columns:** `claim | value | verified-on`. A blank `verified-on` means **not yet verified**. Do not quote a blank row.
- **verified-on states:** `<date> verified locally (probe <area>/<id>)`, `EXTERNAL, not checkable here`, or `(partial — see value)`. Probe ids point into the author-only archive `~/.cache/dafny-verus-learn-0/author-probes/<area>/<id>/`, which holds the input, `cmd.txt`, `stdout.txt`, `stderr.txt` and `exit.txt` for each run.
- **Provenance:** every value in a verified row was captured on 2026-10-03, or on the date its `verified-on` cell names, from a command run on this host: the pinned toolchains that `scripts/get_toolchain.sh` installed, or the host tools at the versions in §1.4. Nothing is copied from documentation. Rows that quote help text say so.
- **Install / check:** `scripts/get_toolchain.sh dafny|verus [--check]`. It prints only the binary path on stdout.
- **Limits used when a row was captured.** DV0 Dafny probes ran with `--resource-limit 1000000`; Verus probes with `--rlimit 10`; the BigNat spikes with `--resource-limit 5000000` (Dafny) and `--rlimit 2` (Verus). A row that quotes an out-of-resource outcome or a resource count holds only at its own limit (§2.5). Goldens must be re-captured at the course pin before a chapter quotes them.
- **DV1b and DV1c rows (2026-10-04).** Rows or sentences dated 2026-10-04 come from the DV1b and DV1c lanes or from the DV1c records lane's no-solver probes, at the course pins (Δ56: Dafny `--resource-limit 5000000 --cores 2`, Verus `--rlimit 2 --num-threads 1`), every solver job under the `CLAUDE.md` §Resources caps. Their evidence is under `dv1b/` and `dv1c/` in the archive (each has an `INDEX.txt`). A few lane runs kept less than cmd, stdout, stderr and exit; their rows say so and are marked partial.
- **Cheat-corpus rows (2026-10-04).** A row or wording whose provenance names `tests/corpus/<lang>/<ID>` comes from that fixture's runs at the course pins (`docs/design/DELTAS.md` Δ108), one solver job at a time under the `CLAUDE.md` §Resources caps. The fixture is the evidence: its program, and a `manifest.toml` that pins each run's exit code and the sha256 of its normalized output, which `scripts/test_corpus.py --ci` re-checks. The texts quoted from these runs were read from re-runs of the fixtures through the wrappers on 2026-10-04.
- **Related documents:** the DV0 findings are in `docs/design/DV0-REPORT.md`; `docs/design/DELTAS.md` is authoritative over the design and spec where they differ.

## 3. Corrections carried forward

Probe facts that refine or correct the spec or the design (spec §9.3). The complete list, with the claim each one overturns, is `docs/design/DV0-REPORT.md` §4; the changes they cause are in `docs/design/DELTAS.md`. The toolchain lane's entries:

- `verus --help` writes to **stderr**, so a wrapper that captures help or usage text must read stderr. So do `opencode --help`, `opencode run --help` and `opencode debug --help`; `claude --help` writes to stdout.
- `cargo-verus` has no `--version` flag. Identify it by its sha256 (above), or with `cargo verus toolchain list`.
- The `Toolchain:` line and `toolchain` JSON field of `verus --version` always carry "(overridden by environment variable RUSTUP_TOOLCHAIN)", even when the caller's environment sets no `RUSTUP_*` variable. Parse the first word only.
- `dafny run --target py` writes `<stem>-py/` beside the source. Wrappers should run it from a scratch copy so build output never lands in a course tree.
- The Verus release bundles Z3 only; cvc5 and Singular are not shipped, and `by (integer_ring)` is rejected at this pin (W-V10), so nothing in the course can use it.
- `dafny server` writes log files into the Dafny install directory (§1.1), so the IDE or server must not run from the pinned tree, or `get_toolchain.sh` must tolerate and clean exactly that file pattern.
- **From DV1b and DV1c (2026-10-04):** `dafny audit` reports a bodyless declaration without an explicit `ensures` when its result is a subset type such as `nat` (§2.1, row D2); the server's log file name changes with the locale (§1.1); `resolve` rejects `--json-output` and `audit` rejects `--show-snippets` (§2.1, row D6); under `--no-cheating` a dependency's `external_body` is reported in every crate that calls it (§2.2).
