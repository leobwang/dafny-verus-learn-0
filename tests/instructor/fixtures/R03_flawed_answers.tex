\begin{answer}
\textbf{Task shape:} This position paper treats incomplete requests as inputs to a specification-development process. It surveys a spectrum from finite examples to logical contracts and domain-specific languages rather than reporting a new model benchmark.

\textbf{Oracle:} The proof checker is the complete oracle for user intent: any verified contract necessarily says what the user wanted.

\textbf{Trust:} A verifier checks the stated mathematical claim and its library boundary. Choosing that claim and deciding whether the user meant it remain separate judgements; an opaque API contract can be formally valid while omitting a behaviour clients need.

\textbf{Cheat surface:} A one-way membership implication can accept an empty result. Mutant rejection probes such omissions, although a limited mutation family can leave other weaknesses unseen. Universal proof against a weak contract does not repair the contract.

\textbf{Metric:} Completeness is a universal theorem that all incorrect outputs are rejected, independently of the selected tests or mutants.

\textbf{Budget:} The paper reports a new experiment with an identical 600-second and 32-call budget for every model.

\textbf{Variance:} The summary provides no repeated-run spread for a new experiment, because there is no new experiment here. Its reported TiCoder significance value concerns surveyed prior work and is not a confidence interval for specification quality.

\textbf{Artifact:} The identified object is the position paper, arXiv2603.17150, and the cited prior systems. The excerpt supplies neither a new benchmark release nor an immutable code revision or reproducibility manifest for this proposal.
