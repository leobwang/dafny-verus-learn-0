\begin{answer}

but $\mathit{Ramp}(2) = 2$, so it is not sound. \\
$Q_2$: sound? no \quad complete? yes \quad pairs: $(-1, 0)$ meets $y \ge 0$ and

$Q_5$: sound? no \quad complete? no \quad pairs: $(-2, -2)$ meets $y = x$, but
$\mathit{Ramp}(-2) = 0$ (not sound); $(-2, 0)$ is the real output and fails

\textbf{(c)} A client wants $Q_4$: it is the only one from which it can
conclude the exact result. The implementer has the easiest time with $Q_1$,
which the real result meets almost without proof. The caller is helped by
every output the specification rules out, while the implementer pays for each
one, so the two pull in opposite directions.
\end{answer}

\section*{Problem B2 (paper card)}\label{ans:B2}
\begin{answer}
\textbf{Source:} cheatsheet entry 05.5, lines 2005--2031 (the pinned range).

\textbf{Task shape:} A Lean 4 benchmark of 189 hand-checked tasks, each asking
for code, a specification and a proof; 108 tasks (VERINA-A) were translated
from Dafny and 81 (VERINA-B) adapted from course submissions.

\textbf{Oracle:} Lean checks code and proofs; a generated specification is
compared with the reference pre- and postcondition for soundness and
completeness, first by an LLM-written proof, then by \texttt{decide} on test
cases, then by property-based testing, with what is left marked unknown.

\textbf{What is trusted:} Lean, the single reference specification of each
task, and its positive and negative tests (full line coverage).

\textbf{Cheat surface:} A specification that just restates the code; the
benchmark scores end-to-end proofs against the ground-truth specification so
that this cannot make a proof trivial. The spec metric itself is test-based,
with up to about 30\% unknown on hard postconditions.

\textbf{Metric:} pass@1 per stage and end to end; for o3, 72.6 on code, 52.3
on specifications, 4.9 on proofs and 3.2 end to end. Proofs certify under 4\%
of specifications, against 41.6--51.0\% by testing.

\textbf{Budget:} Only the refinement comparison is costed: equal tokens
against COPRA (o4-mini, 350k), and 64 refinements for one prover. No other
compute figure is given.

\textbf{Variance:} Not reported in the range; repeated runs or intervals would
be needed.

\textbf{Artifact:} The benchmark itself, in its two parts.
\end{answer}
