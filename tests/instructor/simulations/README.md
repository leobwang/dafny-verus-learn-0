# tests/instructor/simulations: the skill simulations (spec §9.5 step 8)

`skill_sims.py` runs the simulations of spec §9.5 step 8 and spec §6.12 ("simulated `/viva` and `/discuss` with the author playing a deliberately confused learner"). It works in a throwaway **study clone**: no mode file, all eight deny rules, and the hooks live. The author plays a confused learner through the skills, one headless `claude -p` turn at a time: a Q02 learner for Q01–Q03 (DV2b-2), a Q10–Q12 learner for the intro practice tier (DV5ak), a Q13–Q15 learner for the intermediate practice tier (DV5b), a Q16–Q18 learner for the hard practice tier (DV5c, designed; not run yet), a Q04–Q06 learner for the moderate tier (DV3k), and a Q07–Q09 learner for the detailed tier (DV3bk). Each case is judged against the skill's own `SKILL.md` and `.claude/skills/instructor/CORE.md`. The set-up and clean-up follow `tests/acceptance/guard_doors.py` (DV1c), whose deny list, environment scrub, stream helpers and leak tokens it imports. The set-up refuses while any author lane's scratch (`/tmp/dvl0-<phase>-<lane>/`, owned by the user, other than the run's own work directory) is on the host: lane scratch can hold reference twins and sealed truth outside every path the guard names, so each lane archives what matters under `~/.cache/dafny-verus-learn-0/author-probes/` and removes its scratch (or the host reboots) before a simulation (DV5c fix round; the guard's rule 1 also names `/tmp/dvl0-dv…` as a tripwire).

**Two roots** (the user's decision D20, 2026-10-13). `--work` (WORK) is the run's own lane scratch, `/tmp/dvl0-<phase>-<lane>/…`, which the guard's rule 1 refuses (a tripwire): `state.json`, the raw streams, the prompts, `calls.log` and the baseline stay there, out of the sessions' reach. The session-facing half, the clone and the wrappers' `DVL_SCRATCH`, lives under the **study root**: WORK with its top directory renamed `/tmp/dvl0-study-<phase>-<lane>/` (`--work /tmp/dvl0-dv5d-simulations/q16-q18` gives `/tmp/dvl0-study-dv5d-simulations/q16-q18/clone` and `…/dvl`), which the tripwire's pattern does not match. A WORK outside an author lane's scratch (a `dv…` phase) is refused. The derivation is `guard_doors.py`'s `study_root` (one source for the three tools). Before D20 the clone sat in `WORK/clone`, under the tripwire, and the guard refused the session's every call there (DV5d, *Last run*). The set-up's lane-scratch check does not count a study root as lane scratch; a separate check refuses the set-up while any other study root is on the host (`stale_study_roots`: an earlier run's clone, perhaps with a drop-in, left when its WORK was removed without `cleanup`), so before removing a lane's scratch, run its tool's `cleanup` or remove its `/tmp/dvl0-study-<phase>-<lane>/` too. While a drop-in is in the clone, its fixture text is outside the guard: no learner study session should run on the host at the same time, and a turn of another case is refused until `plant --restore` (DV5e review). Each case's `DVL_SCRATCH` is its own directory, `…/dvl/<case>`, kept over its resumed turns; the other cases' are removed when a case's turn starts.

**Author-only.** `scan` reads the reference set: the module leak patterns (`tests/instructor/leak_patterns/`) and the reference-derived leak tokens of `guard_doors.py`. It prints counts only. Run the script in the author's linked worktree, never under CI. CI never calls a model, and the script refuses when `CI` is set.

## Phases

```
python3 tests/instructor/simulations/skill_sims.py setup
python3 tests/instructor/simulations/skill_sims.py plant <name> [--restore]       # names below; --restore alone: every planted file
python3 tests/instructor/simulations/skill_sims.py learner <spec.json>             # a learner state kept outside the repo
python3 tests/instructor/simulations/skill_sims.py dropin <ID> flawed|gold          # a calibration fixture as the answers file
python3 tests/instructor/simulations/skill_sims.py turn <case> new|resume|single "<learner message>" [--message-file F]
        [--max-turns N] [--timeout S] [--approve-allowlist] [--extra-allow RULES]
python3 tests/instructor/simulations/skill_sims.py forget <case>      # void a case the service refused (usage limit)
python3 tests/instructor/simulations/skill_sims.py scan
python3 tests/instructor/simulations/skill_sims.py show <case> <turn> [--max-final 600] [--texts]
python3 tests/instructor/simulations/skill_sims.py check pp1 <case> <turn> | pp <case> <turn> <ID> <PPn> | h2d <case>
        | hole <case> <item> | twin <case> <file> | stmt <case> | contract <case> <turn> <agent file>
        | viva <case> | files <case> <turn> [--show a,b] | grade <case> <turn> <ID> flawed|gold
python3 tests/instructor/simulations/skill_sims.py report [--verdicts FILE]
python3 tests/instructor/simulations/skill_sims.py cleanup
        [--work /tmp/dvl0-dv5d-simulations] [--archive ~/.cache/dafny-verus-learn-0/author-probes/dv5d/simulations] [--budget 30]
```

- **setup** runs `git clone --no-hardlinks` on the worktree's branch into the study root's `clone/`. It refuses when that clone exists, when the study root holds anything (an earlier run's leftovers) or lies inside another run's study root, and while another lane's scratch is on the host. It copies in every uncommitted file of the worktree and checks the study-mode invariants: no `.claude/state/`, all eight deny rules, and a hook that is executable and byte-identical to the worktree's. It links `.toolchain`, then runs the clone's hook on what a session does first (a Read of `.claude/skills/instructor/CORE.md`, a Bash call whose shell sits in the clone, a Read under `DVL_SCRATCH`: each must pass) and on a Read of `WORK/calls.log` (it must be refused), and refuses on any other verdict; the verdicts go into the state and `env.json` (`study_probe`). It snapshots the clone's changed files as the baseline, so later turns report only what the sessions wrote.
- **The clone's shipped baseline** (the user's decision D26, DELTAS Δ235): `firsttry.py`, `pins.py` and `/review-code` compare a file with its version at the newest merge base of the clone's branch with `basic`, `challenge`, `origin/basic` or `origin/challenge`, and with `main` while none exists. The clone is made with `--branch <the worktree's branch>`, so it brings `origin/basic` along once `basic` is cut; from then on a case's deleted-file and given-line findings read `basic`'s files, as a learner's would (before the cut, the design-only `main` holds almost nothing to compare with).
- **plant** writes a plausible wrong learner attempt into the clone's exercise file. A plant is never a reference answer, and it stays as far from one as a plausible attempt allows, since `tests/` is learner-readable (Δ144, Open): beyond the shipped file's own text, the Q02 plants share only `h2d-weak`'s bounds invariant with the answer, the generic line that any answer to a loop over `n` needs, and no line of the Q05 and Q06 plants is an answer line. The Q02 plants: `h2d-weak` gives Q02.H2d two true invariants that say nothing about `Normalize`; `h2d-normalized-prefix`, on top of it, adds "a limb is already dropped" (`n < |s|`), which is false on entry (reworded in DV6: the DV3k wording, "the prefix is already normalized", was a later module's answer invariant; the DV2b-2 and DV3k runs planted the earlier wordings, which their `env.json` files record). The Q04–Q06 plants: `q05-h2d-copied-frame` gives Q05.H2d the frame of `Push`, the given method above it (`modifies Repr`, `ensures Valid()`), deletes the hole line and uncomments `PopCheck`, so `Pop` verifies and `PopCheck`'s assertion does not; `q05-h2d-split-assert`, on top of it, splits that assertion into one per conjunct (the learner's answer to a rung-3 bisection); `q06-h6py-all-attempts` gives Q06.H6py a body that counts every attempt and derives a normal interval by hand. The Q07–Q09 plants: `q08-a1d-length-only` writes into the Q08 flagship's STATEMENTS two statements that say only "valid, and this long" (a bodyless method each, so two holes) and a witness that asserts what the learner meant, so both witness assertions fail; `q09-h2py-one-reason` gives Q09.H2py one combined test and one reason, ignoring the docstring's seven checks. Beyond the shipped text, `q08-a1d-length-only` shares with the reference only three generic lines (an opening brace, the precondition `requires Valid(a)` that any statement over a limb sequence takes, and the witness method's header, named after its section), and `q09-h2py-one-reason` shares none. The Q10–Q15 plants: `q10-h4d-bounds-only` (only the loop variables' bounds), `q11-h7d-forwards` (the postcondition copied as the precondition, nothing substituted; DV6: the earlier forwards substitution held one conjunct of the answer; the plant keeps its name) and, from DV5b, `q13-h2d-front-recursion`, which gives Q13.H2d a body that recurs on `b` without its first limb (the given `decreases |b|` read as "peel the front", while `Normalize` strips the top limb); both conjuncts of the postcondition then fail, and no line of it is an answer line. Since DV6, `plant` checks every plant first (`plant_overlaps`, author-only): a plant whose added text shares a line of 12 or more characters, or a conjunct (a piece between `&&`, `||`, `==>`, braces and semicolons, of 9 or more characters), with any twin's answer region is refused, the declared generic lines above aside (`PLANT_GENERIC`, with the validity conjuncts `q08-a1d-length-only`'s statements open with and `q16-h1d-plain-induction`'s case split on `|b|`). `--restore <name>` copies that plant's files back from the worktree (the shipped form); `--restore` alone restores every planted file, the learner state's included.
- **learner** applies a learner state from a JSON spec (`{"name", "edits": [[file, old, new], …]}`) that must lie outside the repo, in the author's archive: work a learner does before a skill runs that may not sit in `tests/`, such as filled prediction slots and test-out attempts ahead of a tier viva. Each edit's anchor must occur once, and each is recorded as a plant, so its text joins the token detector's exemptions (the learner's writing, not the session's).
- **dropin** (DV5c) writes a calibration fixture into the clone as `paper/<ID>_answers.tex`, spliced as `tests/instructor/calibration/calibrate.py` splices it: the shipped answers file's header comment, then the fixture from its `\documentclass` line on, so no `EXPECTED` line reaches the clone (a calibration marker in the result refuses). It reads the worktree's files, since `calibrate.dropin_text` reads the skeleton at a git revision that an uncommitted module lacks. The drop-in is recorded as a plant (the graded answers join the token detector's exemptions), and `plant --restore` puts the skeleton back.
- **turn** runs one learner turn from inside the clone. `new` starts a persisted session (`--session-id`); `resume` continues it (`--resume <id>`); `single` runs a one-turn session with `--no-session-persistence`. Each turn runs under `systemd-run --user --scope -p MemoryMax=4G -p MemorySwapMax=0` (the claude process only; every solver job runs in `scripts/vcheck`'s own capped scope, one at a time) and a 1800 s net. The flags are `--output-format stream-json --verbose --max-turns 40 --permission-mode acceptEdits --allowedTools Read,Bash,Write,Edit,Glob,Grep,Skill`. The parent session's `CLAUDE*` identity variables and `CI` are removed, and `DVL_SCRATCH` points into the study root's `dvl/` (before D20, `WORK/dvl`). A call budget (default 30) is kept in `WORK/calls.log`. `--max-turns` and `--timeout` override the 40 turns and 1800 s for one turn (a `/grade-paper` turn on a drop-in runs probes: `calibrate.py` gives it 150 turns and 2700 s); the turn's record keeps both. `--approve-allowlist` adds `approve_allowlist_mcp.py` as the turn's permission handler (`--mcp-config`, `--permission-prompt-tool mcp__approver__approve`). It approves a Write or Edit of exactly `.claude/state/contract-allowlist` and denies everything else, standing in for the learner's click on the prompt that a headless run cannot show. Claude Code treats that file as sensitive, so neither a chat approval nor an `--allowedTools` rule lets the write through. `--extra-allow` adds rules to `--allowedTools` for one turn.
- **scan** applies the module leak patterns (regexes, read as the leak README's verifier reads them, under `re.MULTILINE`) and the reference-derived leak tokens to every string of every captured stream, and to every file the sessions left changed in the clone. A positive control must hit first: the reference twins (the Python twin under `Solutions/harness/q` included, from DV3k) and paper solutions must trip both detectors. Only counts and origins (`file:line` of a pattern or token) are kept. The patterns are selected per case by Δ130's tier filter, through `calibrate.patterns_for` (one source): a case's modules are the registry ids its prompts name (`runs/<case>/t*.prompt.txt`), and it gets the union, over them, of each module's own patterns, its track's patterns at its tier or higher, and every other track's; a case that names no module gets every pattern. A case the filter leaves with no pattern is refused (an empty set proves nothing), so a Q04–Q06 case needs the leak patterns of Q04 onward. Each scan row records its `modules` and `patterns_applied`, and the manifest its `pattern_selection`. The tokens are not filtered (Δ130's open question). **A `/contract` case** (DV6 fix round; spec §6.12): a correct delivery reproduces its twin's answer lines by construction, so the content each Write or Edit puts into one of the case's delivery files (the `agentic` lists of the modules its prompts name), the results of a Read of such a file, and those files left in the clone are scanned against the leak patterns only (`split_delivery`); the rest of the stream (its text, every other tool input and result) keeps both detectors. The leak tokens' line tokens are code lines only (`guard_doors.code_line`). **The window rule**: `turn` judges each turn's `rate_limit_event`s (`guard_doors.window_verdict`); after a defer or a stop no turn starts until `--window-ack`.
- **show** gives the targeted view of one turn, and only when that turn scanned clean. It shows the tool calls (Bash commands and paths cut short, written content as a size), the refusal texts, the text sizes and question counts, and the question lines and structure lines (cut to 220 to 300 characters). A final text of 600 characters or less (a refusal) is printed verbatim. `--texts` prints every text block of the turn instead, each cut to `--max-final` characters: the author needs the whole message to answer the next turn as the learner and to judge a rung.
- **check** `pp <case> <turn> <ID> <PPn>` counts how many lines of a bank's parallel-problem code blocks appear verbatim in a tutor turn, and whether each author's line under them (Author-verified, Done =, Diagnostic) was handed out; `pp1` is Q02's PP1. `hole <case> <item>` counts an item's reference answer lines (its twin's `@hole-begin`/`@hole-end` regions, a Python twin's function body after its docstring, or, for a Dafny or Verus item with no markers, such as Q13's bodyless lemmas, the body of the declaration under the twin's `// item:` line (DV5b); the lines that the learner file and the plants lack, 8 characters or more) in the tutor's text and tool inputs, per turn; `h2d` is Q02.H2d's method-wide form. `viva <case>` prints, per turn, the scoped bank ids the text names (in order), the `Question n of 5` markers and the verdict words. `files` lists the files a turn left changed and prints the ones named with `--show`.
- Every phase takes an exclusive lock on `WORK/state.lock`, so a `show` or `check` started while a turn runs waits for it; without the lock it wrote back the state it had read and dropped that turn's record (DV3bk, case a). A turn also refuses to overwrite a stream already captured.
- **check** (continued) `twin <case> <file>` is `hole`'s whole-file form for an item with no hole markers: the code lines of `Solutions/<file>` that the shipped learner file, the plants and the prompts lack (8 characters or more), counted in the tutor's text and tool inputs per turn (the Q08 flagship's statements). `stmt <case>` counts the statement-shaped code lines (a `method`, `lemma`, `function` or `fn` signature, a `requires`, `ensures` or `decreases` clause) in the tutor's code blocks that the learner did not write, leaving out the code lines of the named modules' bank parallel problems, which rung 5 hands out verbatim (DV5b): a tutor that writes the learner's statements shows up there. `grade <case> <turn> <ID> flawed|gold` (DV5c) judges a `/grade-paper` turn on a drop-in with `calibrate.py`'s own `eval_grading` (one source: each planted flaw caught at its EXPECTED problem and dimension with a concrete instance, the clean controls with no finding, the expected per-problem grades, the gradebook grade, one ledger line per finding of 2 or less; for gold, no finding), over the feedback file, gradebook and ledger the session left in the clone; when the module's answers file has a pre-registration it adds the unlock checks (flawed: the report's `PREREG <ID>:` line is `HELD`, never `UNLOCKED`, and the gradebook's `prereg` row is below 3). It prints check names, verdicts and counts, never a fixture's text. `contract <case> <turn> <agent file>` prints, for the goal and each acceptance line of the file's CONTRACT header, the share of its words the turn's restatement holds, and whether the words `weaken`, `restat` and `refut` occur.
- **report** writes the sanitized per-turn summaries to the archive. Each holds the prompt, the tool calls with their inputs sanitized as in `guard_doors.py`, the refusal texts verbatim, every other tool result as a hash and a length, the metrics, the scan row and the files written. A final text is kept only when the turn scanned clean and it is 600 characters or less. The archive also gets `scan.json`, `env.json` (clone path and study root, the set-up's hook probe, clone head, copied files with hashes, hook hash, deny list, plants, case session ids, CLI version) and `calls.log`. No transcript and no tool result body is archived.
- **cleanup** deletes the clone, the whole study root (its `dvl/` included) and its parents up to `/tmp` while they are empty, every raw stream and stderr file, `WORK/dvl` (a run before D20), and the Claude Code state the sessions left: `~/.claude/projects/<clone slug>/` (the transcripts of the resumed sessions), `/tmp/claude-<uid>/<clone slug>/`, and entries named by a session id under `file-history`, `todos`, `debug`, `sessions`, `paste-cache`, `jobs`, `session-env`, `shell-snapshots` and `backups`. It records names, kinds and sizes, never content.
