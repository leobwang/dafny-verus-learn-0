# q18_retrospective.md — the capstone's retrospective (Q18; QPLAN §28.3 step 6)

Learner-owned: you write every line; no AI session writes it. Write it after the ship step
(the CLI over the verified core), before contract v2 (`### Q-v2 — Q18` in `CLAUDE.md`, by
hand) and before `research/TRUST.md`'s final section. `/grade-paper` and the tier viva read it;
no script does.

How to fill it (part of the 15-minute ship step; one or two lines per field, each pointing to an
artifact: a commit, a run directory, a file and line, or a command and the output it showed):

1. TIMELINE: the round's steps with their dates and commits (blueprint graded; statements
   committed; review run; statements re-committed, if any finding changed one; co-developer run;
   the plant; ship).
2. REVIEW: each finding of the statement-only review, and what you did with it.
3. CO-DEVELOPER: where the run followed your blueprint, where it left it, and what each hint you
   gave it was (quoted from the transcript).
4. PLANT: the plant (in your own words, never pasted here before the tier viva's opening), the
   theorem that failed, the line it failed at, and whether that line localizes the plant.
5. TRUST: what the CLI trusts that the verified core does not prove (each item listed in
   `research/TRUST.md`'s final section).
6. NEXT: what you would state differently in a second round, and why.
