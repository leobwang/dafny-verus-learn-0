# expected/ — pinned expectations (author-written, CI-checked)

Everything here pins a **verified tool behaviour** that the course quotes or grades
against. The files are frozen for every study session (guard rule 2f): only the
author writes them, with the commands below, in the authoring worktree. Several of
them describe what a tool prints, which can answer a prediction: **do not open
`expected/` for a module whose predictions you have not committed yet** (README,
*Predictions first*).

| file | what it pins | written by | checked by |
|---|---|---|---|
| `<ID>.pins` | one line per verdict slot, `<K><n><lang>  salted-sha256 <64 hex>`: the sha256 of `"<module id>:<item id>:<answer>"` (for example `Q04:P1dv:verified 2`, from the tools suites' synthetic Q04), the answer normalized (trimmed, internal whitespace collapsed to one space). The salt keeps equal answers of two items apart and keeps the well-known hash of a short string out of this directory. **Never the answer itself.** The legacy unsalted form `<K><n><lang>  sha256 <64 hex>` (pins written before the DV2a fix round) is never read: DV2b retired its reader, so a legacy pin matches no answer, and `pins.py --ci` reports it as a problem in every run; none is left here. | `scripts/pins.py --update --ref --module <ID>` (from the reference answers) | `scripts/firsttry.sh <ID> --check` (first tries), `scripts/pins.py <ID>` (enabled slots), `scripts/pins.py --ci` (every pin names a verdict item; every verdict item has a pin; every pin equals the hash of its reference answer whenever the reference slot file exists, in the author's context only: elsewhere that half is skipped and the summary says so), `scripts/pins.py --ref` |
| `<repo path>.expect` | a sidecar golden: the whole normalized output of the pinned verifier on one file (a W item, a card failure, a demo, a planted file; **never a file whose items carry prediction slots**, a P item, a verdict switch, a value, obligation or error slot, since its output is their answer: `pins.py --update` refuses one, and `pins.py --ci` and `reference_lint.py` flag one): exit code, verdict, stage, counts, holes, then the diagnostics (Dafny: `file:line:col: severity: message`; Verus: the normalized `--output-json` document and rustc diagnostics). Normalization (DELTAS Δ36, Δ37, Δ59): diagnostics sorted by position, file names reduced to base names, the Dafny `uri`, the Verus build-info and timing blocks, the `aborting due to` line and vstd trigger notes dropped, JSON keys and note lists sorted, scratch and checkout paths redacted. The first line after the comment header is `command: verify` (or `command: test`). **Sealed sidecars**: the sidecar of a card demo that carries `// after: <item id>` lines (a demo whose output settles that prediction) shows **no output line**: after `command:` come only an `after: <item ids>` line and an `outcome: salted-sha256 <64 hex>` line, the hash of `"<module id>:<after ids, comma-joined>:<repo path>"`, a newline and the whole normalized output (exit code, verdict, stage, counts, holes and every diagnostic). Drift in any of them fails, and none is readable, since for several divergence demos the diagnostics alone settle the prediction (DV2b; a chapter that shows such a demo's output quotes a real run in a pinned fence, after the predict box). | `scripts/pins.py --update <file>` (it seals a demo with `after:` lines by itself) | `scripts/pins.py --ci` (a sidecar whose source is gone is stale: an error; an unsealed sidecar of an `after:` demo, a sealed one of a file without `after:`, or a sealed one that still shows output lines (the pre-DV2b form), is an error) |
| `<ID>.chapter.toml` | the chapter pins (DV2b; spec §3.15): one `[[entry]]` per tool output the chapter quotes. In the chapter, an output fence is **bare** (no language tag, at column 0) and preceded by the line `<!-- pin: <entry id> -->` (blank lines between allowed); source fences carry their language. An entry: `id`; `cmd`, the exact command as the learner types it (`scripts/vcheck`, `scripts/vaudit`, `scripts/specfreeze`, `scripts/firsttry.sh` with `--report` or `--lint-hollow` only, never an author-only or state-writing mode; or the pinned `dafny` / `verus` binary on scratch files); `cwd` (`"root"`, the default, or `"scratch"`: a fresh directory holding the entry's scratch files, `[entry.scratch."<name>"]` with one of `text = "…"`, `copy = "<repo path>"` or `fence = "above"`, the nearest language-tagged fence above the pin line); `display` (the command line the fence shows; default `cmd`); `inputs` (repo files the output depends on beyond what `cmd` names); `answers` (prediction ids this output settles: `chapter_lint.py` keeps the fence after their predict boxes; the `after:` lines and slots of a named specimen count by themselves); `excerpt = [first, last]` (the fence shows those output lines, then a `...` line; the chapter says what was cut); `guards` (`"open"`, the default: run as the learner sees it once the predictions it waits for are recorded, the H5 guards lifted for that one run; `"closed"`: quote the refusal a learner meets before); `note`; `[entry.normalize]` with `prompt` (default true: a first line `$ <command>`), `exit` (default false: end with `$ echo $?` and the exit code), `drop` (regexes: output lines to drop) and `replace` (`[regex, text]` pairs for volatile tokens, which the chapter names). The fixed normalization drops ANSI codes and trailing blanks and redacts the scratch directory and the course root to relative paths, any other scratch path to `<scratch>/…` and `$HOME` to `~`. A `kind = "recorded"` entry quotes output no course command can re-run (a guard refusal from the author's acceptance archive): `source` names the record, the fence body is the author's verbatim copy, and only `normalize.replace` applies. `[entry.pinned]` is written by the tool, never by hand: `body`, the sha256 of the fence body, and `[entry.pinned.inputs]`, the sha256 of each input (a repo path, `scratch:<name>` for a scratch file; `absent` for a missing file) as captured; a quoted refusal (`guards = "closed"`) counts the calibration file of each prediction it waits for among its inputs. Hashes and commands only, never output. | `scripts/pins.py --update --chapter <ID> [--entry E …]` (author-only: runs each entry, writes its output into the chapter's fence and the hashes here, and rewrites this file canonically, so notes go in `note`; a recorded quote is checked line by line against its record) | `scripts/pins.py --chapter <ID> [--entry E …]` and `scripts/pins.py --ci` (every pin line names an entry, every entry is quoted once, each fence body hashes to its capture, and each entry is re-run and compared with its fence; an entry whose inputs changed since the capture is stale: a problem in the author's context, which re-captures (spec §3.15 rule 9), and skipped with a count elsewhere, where the change is the learner's own work; a recorded quote's record is read in the author's context only); `scripts/chapter_lint.py <ID>` (the static half, with the chapter skeleton) |
| `<ID>.freeze` | the statement freeze (spec §11.1 row 29, Δ44): one sha256 per statement (signature and clauses, token-normalized, a definition's body included) of every Dafny, Verus and Python file the registry lists for the module (its exercises, specimens, exits, agentic and harness files), as shipped, each `[[file]]` with its `lang` (`d`, `v` or `py`); `open_bodies` names function holes pinned without their body: a bodyless Dafny function or predicate, and one shipped with a placeholder body that its twin replaces (QPLAN §30 Q52), whose header is compared exactly and whose body is ignored. A Dafny module that carries the comment line `// specfreeze: frozen-imports` (QPLAN §30 Q62) is pinned in a `[file.frozen_imports]` table, `{ module = [sha256 of each import statement of the module and of every module nested in it] }`; `--check` reports `freeze-imports-changed` for an added, removed or changed import (their order is free) and `freeze-missing` for a marked module that is gone, and `--against` and `--lab` apply the frozen file's markers the same way. A Python statement is a function's or class's signature (name, parameters with annotations and defaults, return annotation, decorators, bases), never a body or docstring, so filling a hole changes none. A Dafny declaration that is opaque (the `opaque` modifier or a `{:opaque}` attribute, one statement either way) is pinned as sha256("opaque\0" + its plain hash), so a change of opacity is a change of statement. A file with a Dafny frame annotation hole (Δ137, QPLAN §6 Q22) also carries `open_frames = [...]`, the methods whose added `modifies` and `ensures` clauses are accepted, and a `[file.frame_ensures]` table pinning each such method's shipped `ensures` clauses, which must stay verbatim and in order; both keys are written only for a file that has open frames, and the schema stays 1. A file with a statement hole completed by added clauses (QPLAN §6 Q44: Q07.H7v, Q08.T1v and H3v) likewise carries `open_specs = [...]`, the declarations (exec fns and trait methods included) whose twin statement differs from the shipped one by added `requires` and `ensures` clauses only, taken by `--pin`, and a `[file.spec_clauses]` table pinning each one's shipped `requires` and `ensures` clauses, which must stay verbatim and in order; the statement hash of such a declaration is its spec core (the signature and every other clause), and these keys too are written only for a file that has open statements. A `decreases` added to a declaration that shipped without one is no change (`specfreeze` compares a changed statement again with the file's header measures blanked); a shipped measure, Dafny's `decreases *` and a Verus `when` or `via` stay frozen | `scripts/specfreeze --pin <ID>` (author-only: it refuses outside `CI=true` and the author's worktree, so a session cannot re-pin a weakened statement) | `scripts/specfreeze --check <ID>` |
| `<ID>.counts` | the count pins (Δ11), schema 2: one `[[unit]]` per verification unit of the module, with `reference_verified` (the reference twin's gate count: Dafny tasks, Verus `verified`), `symbols` (the learner-declared declarations with a contract that ran a task in the twin's gate: Dafny lemmas, methods, functions and predicates with an `ensures`, and function definitions; Verus fns with an `ensures`, and recursive spec fns) and `min_verified` (the gate's floor: one per pinned symbol, not the twin's count, because a learner may add helpers and a twin's reference-only helpers count tasks a learner need not have); and one `[[file]]` per Dafny and Verus file of the module that is not a specimen (the orchestrator's Q8 decision): `path`, `role` (`exercise` for a file of a unit, `check` for a given-only check unit, `exit`, `agent`) and its **shipped state** in the learner loop, `verdict`, `holes` (tool-counted: the count the file's header and the chapter state) and `errors` (an agent file's RED state). Symbol names and counts only, never code. A schema-1 file (units only) is still read for the units; `pins.py --ci` reports it as pinning no file. | `scripts/vcheck --ref --pin-counts <ID>` (author-only; the units from the twins, the files from the learner files as they stand: run it on the files as shipped) | `scripts/vcheck --gate` on a unit (a pinned symbol that ran no task, or a count below the floor, fails: a deleted lemma or hole; a unit with no pin fails), `scripts/vcheck --ref` (a twin that no longer gives the pinned count: a stale pin), `scripts/vcheck --shipped <ID> [d|v]` (every file in its shipped state: same verdict, holes and errors; `scripts/ci.sh`'s verify jobs), `scripts/pins.py --ci` (one pin per unit and per file with its role, no pin for anything else, every pinned symbol still declared) |
| `<name>.audit` | a pinned assumption-audit report (spec §3.13; a `/contract` acceptance line): one `path:line: kind` line per finding, sorted; an empty report is a clean audit | `scripts/vaudit --write expected/<name>.audit <target>` | `scripts/vaudit --compare expected/<name>.audit <target>` |
| `verus_trust.toml` | the Verus trust allowlist (`[[trust]]` tables: `path`, `symbol`, `kind`, `reason`, nothing else): the given-layer holes a crate may trust. `path` is relative to the course root and lies under `verus/given/` (a module crate's own hole is never trusted); `symbol` names a fn (or `assume_specification`) of that file; `kind` is a hole kind (`assume`, `admit`, `external_body`, …); `reason` is non-empty; no entry repeats another. A malformed entry, a deleted path or an unknown symbol fails every Verus run that loads it. Absent = an empty allowlist. | the author | `scripts/vcheck` and `scripts/vaudit` (a trusted dependency hole is an info line, any other a finding), and `scripts/vaudit --check-trust` (CI; dvl.verus.check_trust): every entry must match a hole of the given layers under `verus/given/`, and every given-layer hole must be on the allowlist (no given crate and no entry: nothing to check, a loud pass) |

Rules (spec §8.3, §8.5):

- **A pin or waiver that matches nothing is an error**: a pin line naming no verdict item, a sidecar whose source is gone, a chapter pin line naming no entry or an entry quoted nowhere, a chapter pin file of a planned module, a freeze entry for a file the registry no longer lists, a count pin for a path that is not a unit of its module (or a module that is not armed), a pinned symbol no longer declared, a trust entry that matches no hole.
- **Empty sets fail where something is required**: `pins.py --ci` with armed modules and nothing pinned, `specfreeze --pin` with no statement, `vcheck --ref --pin-counts` for a unit with no symbol to pin, `update_rubric_pins.sh --check` on a rubric with no pin line or an armed module's rubric missing, `firsttry.sh --lint-hollow --all` on an armed module with no exercise or exit file, and every one of them on a registry that lists no module. When every module is still planned there is nothing to require: `pins.py --ci`, `pins.py --ref`, `firsttry.sh --lint-hollow --all`, `reference_lint.py` (no reference file either), `update_rubric_pins.sh --check` (no rubric file yet) and `vaudit --check-trust` (no given crate, no entry) pass **loudly**, printing "no armed module: nothing to check" (or its equivalent), never silently.
- **What catches a deletion**: `vcheck --gate` against `<ID>.counts` (a deleted lemma or hole of a unit), `specfreeze --check` (a frozen statement gone), and `firsttry.sh <ID> --report --strict` (a marker, slot or check gone, or a whole shipped exercise, specimen or exit file gone, judged against the files as shipped at the newest merge base of HEAD with `basic` or `challenge`, or with `main` while neither exists).
- **Never invent output**: every `.expect` sidecar, every audit report and every chapter fence comes from a real run of the pinned tools (`VERSIONS.md` §1), or, for a recorded quote, verbatim from its record; re-run the writers after a toolchain bump or a change of the course pins (Δ56).
- Mismatch reports print **locations only**, never the pinned content.
- Rubric sha pins live in the rubrics themselves (`paper/rubrics/*_rubric.md`), filled and checked by `scripts/update_rubric_pins.sh [--check]`.

Two markers in learner files steer what is pinned here (DV2a fix round):

- **`// after: <item id>`** (one or more lines in a card demo specimen): the demo settles that prediction. `vcheck`, `vaudit` and `vcheck --test` refuse to run it until the item's first try is recorded (like a specimen's own slots, H5); its sidecar is sealed (above); `firsttry.sh --lint-hollow` checks that each line names a prediction item and sits in a specimen.
- **`// planted: <item id>`** (in an S12 delivery specimen, trailing the planted line or on the line above it): a trust leap planted on purpose for the learner to diagnose. Only the shipping lints honour it (`firsttry.sh --lint-hollow` and `reference_lint.py` drop their findings on that line); `vcheck` and `vaudit` never do, so the instruments still report the leap. It is valid only when it names an S12 verdict P item of its own file.
