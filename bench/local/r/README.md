# Learner-authored R bench cards

R02–R11 each ask for one new learner card. Keep it in a directory named for
its module and your task. A card here is a draft, not automatic admission to
a later lab's benchmark pool. Use the module's declared layer and pinned wrapper.

For R02, preserve five artifacts:

1. A statement naming the inputs, intended result, preconditions and conventions.
2. A stripped problem with the intended learner work missing and the contract fixed.
3. A completed solution that passes the native gate and assumption audit.
4. A positive witness satisfying the preconditions, with its observed check.
5. Negative checks that reject at least one plausible wrong implementation or statement.

Record the actual commands, exits, relevant diagnostics, toolchain and resource
settings. A verifier rejection at parsing is not a semantic counterexample.
Explain what each negative check distinguishes. Keep an original first version
when revising a statement, and explain the revision.

Choose different work from a course hole; do not copy a reference or turn a
renamed exercise into an independent benchmark claim. The course author does
not fill these learner artifacts. Later R lab admission has its own review,
format and pre-registration requirements.

For R04's third card, allow twenty-five minutes. Choose a fresh small logical
or specification task under A1. State quantifier bounds, slice conventions and
both directions of any intended Boolean relationship. Preserve the same
statement in stripped and completed forms, give a nonvacuous positive witness,
and show what plausible wrong claim or implementation each negative check
rejects. Retain the original version when revising it. A parse error is not
a semantic refutation, and this draft is not automatic admission to a later lab.
